# Context

当前跨被试公开协议最佳结果为 `0.85 * plus_pe + 0.15 * frequency_graph_zscore`，固定 OOF AUC=0.803836、F1=0.726616；实验095的 AUC=0.994971/F1=0.996013 来自同一被试35个有标签窗口适配后预测5个窗口，不能直接等价为公开集无标签泛化。目标是在不引入公开标签泄漏的前提下，取长补短，逐步逼近AUC 0.95。

# 推荐实施方案

## 1. 建立严格适配基准

新增 `test/experiments/198_protocol_k_adaptation/`，复用实验057、006和095的数据对齐、subject-wise切分及预测格式。以物理 trial 为分组单位，模拟 k=0/1/2/4 个支持 trial：

- k=0：仅跨被试模型 + 目标被试无标签归一化，作为公开集合法协议；
- k=1/2/4：仅用于估计有标签校准时的上限，不作为当前公开提交方案；
- support/query 完全按 trial 隔离，查询标签只用于最终评分；
- 在外层训练被试内部完成适配规则、模型、方向、阈值和融合权重选择。

输出 pooled/macro subject AUC、F1、HC/DEP AUC、最差被试AUC，并记录每个支持集组合及标签使用范围。

## 2. 加入真正DE特征

新增 `test/experiments/199_de_plus_pe/`。按通道×频带×窗口计算滤波信号方差的高斯近似微分熵，并增加有限的区域/左右差分/频带比值特征。依次比较：

1. DE；
2. DE + 057原有特征；
3. DE + plus_pe；
4. DE + plus_pe + graph；
5. 独立DE模型与现有模型的OOF概率融合。

优先概率融合，避免高维直接拼接压制排列熵。所有特征、标准化和特征选择均在外层训练数据内拟合；k=0公开预测只使用目标被试无标签统计。

## 3. 轻量CNN/BiGRU专家

只有DE路线在5次subject-wise重复OOF平均AUC相对0.803836提升至少0.005后，新增 `test/experiments/200_light_cnn_bigru/`：

- CNN建模频带/DE的局部时序结构；
- BiGRU只建模单个物理trial内部的短窗口序列，不拼接随机公开trial；
- 作为独立概率专家，与DE+plus_pe+graph融合；
- 使用GPU、固定随机种子、无外层验证标签早停。

停止线：平均AUC无至少+0.005、F1下降、HC/DEP任一组下降超过0.02、或不同种子不稳定时停止扩展。

## 4. HC/DEP软专家

新增 `test/experiments/201_hc_dep_soft_experts/`。分别训练HC/DEP专家，用目标被试无标签频谱、DE、PE和图统计估计连续路由权重，不能使用公开身份、标签或5名HC/5名DEP配额强制分配。先做固定50:50，再做嵌套OOF学习软路由；仅当AUC至少提升0.005、F1不降且HC/DEP均无明显负迁移时纳入最终模型。

## 5. 最终固定公开候选

新增 `test/experiments/202_final_public_ensemble/`，只收纳通过nested subject-wise OOF的模型。保留三类文件：

- 保守：057+006当前融合；
- 最优：DE、plus_pe、graph及通过验收的CNN/BiGRU概率融合；
- 软专家：仅在无标签路由通过验收后生成。

最终公开集严格使用k=0，不用公开标签、不根据提交反馈调参、不强制4正4负。每个实验报告记录AUC、F1、trial级指标、HC/DEP指标、是否使用目标标签、外层/内层协议和停止理由。

# 验证命令与质量门槛

每个新实验运行后检查：

- 训练/验证被试不重叠；
- 同一物理trial不跨折；
- cache元数据顺序一致；
- OOF预测数量和公开预测格式正确；
- 所有长期脚本输出进度；
- 报告必须写AUC和F1。

主线执行顺序：198 → 199 → 200 → 201 → 202。任何阶段未通过停止线即停止扩展，保留当前最佳模型作为下一阶段基线。
